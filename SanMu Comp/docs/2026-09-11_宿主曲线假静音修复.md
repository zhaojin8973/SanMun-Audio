# SanMu Comp 0.1.9：宿主曲线假静音修复

用户在 Pro Tools 中发现 Opto、VCA 的输入和输出曲线反复掉到底部，并确认声音正常。本轮修复显示取数时序；四引擎、参数、LISTEN 五秒手动目标及 LEV 平滑行为保持不变。

## 原因与复现

AU、VST3、AAX 使用相同的插件处理器和压缩引擎，但宿主决定音频块到达的时机。现场三种已安装包均为 0.1.8，没有发现版本混装。

原界面每秒取电平 60 次，每次取走峰值后把输入、输出缓存重置为 -100 dB，把 GR 重置为 0。若两次界面刷新之间没有新的音频块，界面就把空缓存画成真实静音。这会造成输入、输出曲线下扎，也会让 GR 曲线在空档归零。

用持续正弦信号、真实插件处理器和真实曲线组件进行确定性的音频/界面调度复现：

- 48 kHz、1024 采样块、60 次/秒界面刷新：180 帧中出现 40 帧假静音。
- 四模式、单/双声道、44.1/48/96/192 kHz、64/256/512/1024/2048/4096 采样块：合计 5910 帧，修复前 1097 帧假静音，修复后 0 帧。
- 前后截图由真实曲线组件生成，数据和截图位于 `docs/verification/2026-09-11/meter-host/before/` 和 `after/`。

上述为可复现的软件时序测试，不是对用户现场 Pro Tools 回调的录制；没有把模拟的 1024 采样块认定为现场实际配置。

## 修复

- 电平缓存用负无穷标记“没有新数据”，真实静音仍为有限电平，零 GR 也仍为有效读数。
- 界面在新音频块之间保持最近有效读数；真实静音块可以立即更新，避免以整体平滑掩盖真实动态。
- 宿主不再回调时，至少 250 毫秒后回落；等待期限随实际音频块时长增加，覆盖超出准备块大小的大块处理。
- 输入、输出、GR 独立处理有效性，音频线程与界面线程交错取数不会把单列的空缓存插成静音。
- 峰值累计仍保留，刷新之间的瞬态不会被后续静音块覆盖。

集成回归补充持续音块大小矩阵，以及真实静音、旁通零 GR、空块、停调回落、16384 采样超大块和重置场景。修改仅涉及电平传递、曲线状态、测试与交付版本号。
