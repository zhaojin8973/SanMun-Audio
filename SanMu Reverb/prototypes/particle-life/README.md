# 生命声场原型

2026-09-08，用户已确认中央生命声场定稿：空气尘埃、梦幻配色、三种观察视图，以及混响和叠加均跟随 MIX。原页面只实现 Concert Hall；新增的完整界面候选位于 `/studio.html`，支持四类八种风格。两者都独立于已安装的插件。

## 完整界面候选

打开 `http://127.0.0.1:5173/studio.html`，查看当前 U12 玻璃设计。深色版保持用户基本认可的发光尘埃，并提高青蓝刻度和淡紫控制强调的饱和度；浅色版使用透明水膜与水下光纹，静止时完全透明，中心扰动向外围展开并随尾音平复。U9 已留存为浅色尘埃基准，U10 首稿保留作历史。保留已认可的字体、旋钮、排版、彩色胶囊和顶部玻璃叠层，品牌仅显示文字。运动、寿命与 MIX 联动继续使用定稿规则。首次默认英文，齿轮设置可切换中英文、浅深主题、界面缩放，并查看帮助；悬停提示可独立选择跟随界面、中文、英文或关闭。原中央页面仍使用原有外观。

- 十五个参数都可操作；旋钮上下拖动、滚轮、键盘方向键调整，Shift 微调，双击或命令键单击恢复参数默认。点击数值可输入，支持秒／毫秒、赫兹／千赫兹等单位。
- 四类、八种风格直接调用现有 C++ 声场，经独立适配层编译。参数平滑与原引擎一致；切换采用两份状态与 50 毫秒等功率淡化。它仍不是宿主插件包装器。
- 类型／风格切换保留当前参数；加载预设会应用该预设的全部参数。共 23 个当前工厂预设，浏览器显示纯湿或插入比例。
- A/B 保存两份状态，可复制；一次旋钮拖动是一条撤销记录。切换 A/B 后开始新的撤销记录。
- 我的预设保存在本机当前浏览器中，可重新加载；尚未与插件的预设目录同步。
- 输入、输出双声道电平来自音频线程。输出表位于混合／旁通之后、浏览器监听音量之前；点击峰值可清除保持。
- 四类共用已认可的生命声场视觉语言，湿声反馈来自各自真实算法；目前没有新增四种不同的空间外形。

运行 `npm run test:studio` 验证交互、八种风格的浏览器与原生输出、声场像素、双主题和响应布局。设计依据与边界见 `../../docs/UI_U1_DESIGN.md`。下文仍说明原中央声场页面。

当前设计见 `../../docs/UI_U12_WATER_SURFACE_POLISH.md`，U9 作为浅色尘埃基准，U10 作为水膜首稿历史。`npm run test:language` 验证双语、独立提示、用户命名、声场保持与四十八组英文布局。`npm run test:glass` 验证双主题材质切换、信号可见度、文字对比度、十二种窗口布局及状态保持；`node --test tests/water.test.mjs` 验证水膜状态机和异常输入。`npm run test:settings` 验证实际缩放、窄窗口约束、偏好保持、帮助、提示与 BYP；原型缩放尚未控制宿主插件窗口。

## 运行

需要 Node.js 22.12 或更高版本。当前目录已安装依赖、已生成混响模块。

```sh
npm ci
npm run dev -- --port 5173
```

浏览器打开 `http://127.0.0.1:5173`。按播放键开始；方形停止键只停止输入，保留混响尾音。上传图标可打开本地音频，文件只在本机解码。循环图标控制素材重复，右侧音量与静音只影响监听，不影响粒子观察。

空间、音色、调制三个标签包含当前 Concert Hall 的参数；回转箭头恢复默认值。右上角可收起参数区。

画面右上角可切换三种观察方式，默认是叠加：

- **原声**：中央珠光短细丝直接读取混响前的输入，快速响应起音，原声结束后及时暗下；不受 MIX 影响。
- **混响**：只显示经过 MIX 控制的混响贡献；MIX 越小尘埃越淡，为 0% 时不可见，为 100% 时完整呈现。
- **叠加**：中央显示输入参考，外围显示经过 MIX 控制的混响贡献。输入不变时，调小 MIX 只让外围变淡；MIX 为 0% 时外围不可见，为 100% 时完整呈现。

视图切换本身不改变试听声音。混响和叠加的尘埃显示强度统一使用与音频一致的等功率湿声增益曲线，并平滑过渡；不改变尘埃的出生、寿命、位置或颜色。MIX 为 0% 时两个视图均不显示尘埃，但内部尾音继续演进，调回来可见其当前状态。

中央是输入参考，不是最终输出中经过 MIX 衰减的干声，因此 MIX 为 100% 时仍可看见中央。未来嵌入辅助轨时，中央代表发送到插件的输入，插件之后的辅助轨推子不在其观测范围。本原型仍未嵌入宿主；叠加也不是整个工程最终干湿比例的精密测量图。

和弦、鼓击和三个频段的短音都是程序合成的测试信号，不是钢琴、军鼓或人声录音。评价实际素材时应使用本地录音。

## 声音来源

`dsp/bridge.cpp` 直接引用当前 `source/dsp/engines/hall/HallField.h`，没有另写混响算法。浏览器的 WebAssembly 模块由这份 C++ 编译得到，在 AudioWorklet 音频线程运行。空间参数使用插件同样的 50 毫秒线性平滑与每 32 个采样一次的配置更新；混合使用 20 毫秒的等功率变化。

试听音量默认 55%，不等于插件输出增益。当前只验证 Hall 纯湿声内核；本原型不是完整插件包装器，不含其他类型、模式切换、宿主自动化或 AAX/VST3 界面。

需要重新编译混响模块时，使用 Emscripten 6.0.9：

```sh
SANMU_EMXX=/tmp/emsdk-main/upstream/emscripten/em++ npm run build:dsp
SANMU_EMXX=/tmp/emsdk-main/upstream/emscripten/em++ npm run build:suite
npm run build
```

临时目录中的工具链可能被系统清理；也可自行安装同版本工具链，并把 `SANMU_EMXX` 指向其 `em++`。构建输出位于 `dist/`。预览服务不需要保留编译器。

开发启动和正式构建会核对 Hall 和四类试听模块对应的源码、适配代码与声音模块校验值；不一致时要求重新编译，防止误听旧版本。

## 视觉行为

- 根据用户第二次反馈，删除前下方喷口、向后飞行的轨迹与地面圆环。声场中心固定，尘埃围绕中心分布在完整三维体积内。
- 声音从中心向外逐步唤亮尘埃，尘埃只缓慢外移很短一段。主要动态来自真实频带能量的明暗起伏，不依靠把整片粒子甩向左右或反复胀缩。
- 局部漂移使用位置和速度连续的随机场，不使用横向周期摆动。声像统计不移动整体中心；立体声相关性只轻微、缓慢地影响宽度。
- 实际输入决定出生率和频段分布；实际湿声约束明暗。尾音不会再次成为生成源。
- 第三版四个宽频带改为柔粉、雾紫、冰青和珠光蓝，相邻色调轻微过渡。颜色固定对应频段，不随时间任意轮换；中央原声细丝采用同频段的较浅珠光色。频谱提取是用于显示的近似分频，不是精密频谱仪。
- 每颗粒子有稳定的方向、位置差异、频段与权重。更改衰减只改变后续能量损失，不重置已有粒子的年龄。
- 尺寸改变展开范围；建立参数改变早期存在感和深处尘埃的进入时序；早期和晚期扩散各自改变对应粒子群的聚散。
- 高频阻尼与低频倍数改变不同颜色的留存；输出滤波通过真实湿声频带反馈到当前可见强度。
- 调制速率控制局部漂移的变化速度，深度控制很小的偏移范围。MIX 控制试听声音及混响、叠加视图的尘埃强度，保留独立分析信号。
- 停止输入保留尾音；切换素材清空旧声场；参数复位保留当前尾音。页面隐藏时停绘，持续保留有上限的粒子状态，恢复时按音频时钟更新。
- 桌面最多 12,000 颗湿声尘埃及 1,000 根原声细丝，手机首次载入最多 4,500 颗及 480 根。尊重系统减少动态效果设置，降低刷新率并关闭调制位移。

轨迹、个体寿命及空间外形是声音的可解释视觉表达，不是声波、真实房间或内部延迟线的逐一重建。首版的频带、外形与颗粒美术仍可继续调整。

音频统计每 512 个采样发送一次，在 48 kHz 下约为 10.7 毫秒，再按屏幕刷新率呈现。原声频带采用 8 毫秒上升、25 毫秒下降的指数跟随，保留两个绘制帧间的短瞬态；这些时间常数不等于端到端延迟。湿声另有较慢的视觉跟随及尘埃渐显，原来的迟缓感既来自混响本身，也来自视觉平滑。

## 验证

```sh
npm test
npm run test:browser
npm run test:views
```

浏览器检查默认使用本机 Google Chrome，需先启动开发服务。可通过 `SANMU_CHROME` 与 `SANMU_PROTOTYPE_URL` 更换路径及端口。

- 生命周期、预延迟、独立分析信号与 MIX 分离、零扩散、容量上限与参数范围自动检查。
- 第二版增加中心稳定、三维分布、连续位移与已有粒子的频谱动态响应检查。
- 第三版增加原声首帧响应、瞬态保留、隐藏页面不积压旧输入、原声归零后混响继续留存、三个视图的画布区域隔离及切换不改变声音检查。
- 本次增加同一音频时刻下 MIX 100%→25%→0%→100% 的画布比较，验证外围变淡、中央输入状态保持、粒子生命与位置不变、恢复 MIX 后不重建声场，以及混响与叠加视图在相同 MIX 下的尘埃强度一致、均在 MIX 为 0% 时不可见。
- 44.1 / 48 kHz、两组参数的三秒脉冲，与原生 C++ Hall 内核逐采样比较。
- 本地音频导入、错误文件、播放和尾音、混合、复位、循环、参数收起与减少动态效果检查。
- 桌面、手机、横屏与宽屏截图，画布颜色像素、运动变化、横向溢出和文字碰撞检查。

报告与截图写入 `test-results/`。自动检查不替代用户的视觉审美确认，也不能替代未来插件内嵌时的多实例性能与宿主回归。
