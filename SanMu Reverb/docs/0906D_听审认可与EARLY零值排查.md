## 确认的局部问题

EARLY控制早期扩散的时延跨度，不是早期反射音量。`HallField.h:265`在零值时将六级早期扩散全部时延缩为零；各级正负混合仍在运行。输出在第341～342行仅选取内部通道3和12，零时延时这两个读出对相同左右输入的叠加结果不同。

直接调用实际`Diffuser`类，单位相同左右输入的早期输出为左-0.143631、右-0.0331457，幅度比约4.33，电平相差12.74 dB。正交混合保证内部总能量，并不保证选出的这两个通道对居中输入等响。零值失衡在44.1／48／96／192 kHz均相同。

实际安装VST3的独立宿主验证：参考固定参数，Attack=50%、Late=100%、Mix=100%，一秒静音预热，幅度0.1的相同左右脉冲；时间以输入脉冲发生时为零。

| EARLY | 48 kHz输入后0～40 ms，左相对右 | 输入后300～3000 ms，左相对右 |
| --- | ---: | ---: |
| 0% | +12.74 dB | -0.25 dB |
| 0.1% | +0.02 dB | -0.25 dB |
| 1% | -0.64 dB | -0.25 dB |
| 5% | +1.28 dB | -0.25 dB |
| 10% | +1.02 dB | -0.25 dB |
| 100% | -0.07 dB | -0.25 dB |

EARLY=0时左右首个有效样本均在22 ms到达，排除这个样例中“左侧先到”的解释。相同左右短噪声也复现12.74 dB失衡；关闭调制仍相同。300 ms以后，不同EARLY的同一脉冲输出最大样本差约1.3e-9，说明问题来自前方支路，未改变后方反馈声场。

12.74 dB仅描述这个隔离前段的左右差，不代表整段混响偏左这么多，也不能直接换算为用户听到的方位角。实际听感还取决于干湿比例、Attack、素材左右相关性和频谱。

0.1%不是通用修复：它在其他采样率下的前段左右差约为+0.68／-1.64／-2.79 dB，且宽带能量接近平衡不等于每个频率、相位均平衡。仅左声道输入在EARLY=0时，前段左右近乎等幅反相；仅右输入也有不同的交叉混合。因此应登记为真实的零值边界缺陷，不能以“低值是自然宽度”一笔带过，也不宜简单给整个右声道加固定增益。

## 本次处理与后续边界

当前已认可声音保持不变，零值问题不阻断用户继续使用常用扩散设置，也不构成重做Hall拓扑的理由。正式完善该端点时，应只针对低EARLY区域设计平衡的早期读出与连续过渡，核查居中、仅左、仅右、单声道合并和多采样率，保持已认可常用设置及晚期声场不变。此段是待办方向，不是已实施或已验证的修复方案。

## Hall另外两个模式的价值判断

当前`HallEngine`没有按mode选择不同声场。三个模式相同参数、新实例、相同输入的逐样本差为零；界面也注明另外两种尚未独立设计。因此当前旋钮已经能完成用户的钢琴、弦乐和人声目标，是Concert Hall自身的可用范围，并非三个独立算法的效果。

模式名称不是严格声学标准。下表为建议的产品目标，尚未实施，也不保证所有现实空间都符合这种概括。

| 模式 | 独立开发应新增的可听价值 | 超出现有旋钮的设计重点 |
| --- | --- | --- |
| Concert Hall | 当前已认可的温暖、绵密、自然展开和融合 | 保留当前声音作为对照 |
| Scoring Stage | 保持演奏轮廓、前后定位和大型录音棚的空间支撑；密集编曲中少遮盖 | 不同的早期反射到达及左右分布、更紧凑的建立过程、分频衰减分布 |
| Cathedral | 更大的空间间隔、更缓慢展开、深远而持续的包围感 | 更大的传播时间范围、不同的反射分组与密度增长、长尾下仍清楚的频率衰减 |

参考依据：维也纳Synchron Stage的官方资料描述约1.6～1.8秒混响、温暖音色与清晰定位，这只是一个具体录音棚的例子：[VSL场地说明](https://www.vsl.co.at/manuals/mir-roompacks/roompack6)。Valhalla对其Cathedral的说明提到更多延迟存储、更展开的建立与衰减、独立合奏式调制：[Cathedral算法说明](https://valhalladsp.com/2021/11/23/valhallavintageverb-updated-to-2-2-0-cathedral-mode/)。这些说明支持从时间与空间结构区分模式，不能用来断言其内部电路已知。

建议先保留Concert Hall的成熟声音，把现有参数已能实现的用途整理为预设；只有在匹配电平、衰减和大致音色后，仍能听到难以由当前参数得到、且有用途的空间差别，才增加独立模式。若扩展，Cathedral通常更容易作为本项目下一项差异明确的目标；Scoring Stage若目前仅靠减少Decay、BassMult和调整EQ即可满足需求，可以先保留为预设方向。开发顺序是建议，尚未获得开工指令。

模式可以复用已验证的基础类，但需要自己的反射分布、延迟配置、参数映射和验证。单一Concert Hall参考无法唯一反推出另外两种声音，三模式数量本身不构成开发理由。
