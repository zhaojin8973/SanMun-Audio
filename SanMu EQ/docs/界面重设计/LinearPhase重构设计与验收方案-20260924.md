# Linear Phase 重构设计与验收方案

日期：2026-09-24。状态：矩阵与动态参考实现完成，AU/VST3/AAX 已安装；低频窄带精度和高负载性能仍未达到全范围发布目标。本文的原方案约束保留为实现与验收依据，不替代宿主验收。

## 1. 决策

建议对 Linear Phase 的音频内核作专项重构，目标是静态均衡、每频段动态均衡及 Stereo/Left/Right/Mid/Side 混用均有明确、正确的音频行为。保留四个同级入口 Clean / Tube / Discrete / Linear Phase，保留现有系列 UI、频谱颜色和交互、频段槽位及参数契约。

这项工作属于音频架构升级，不应把它当作解除一个灰色按钮。完成顺序是数值基准、静态矩阵路由、动态内核、桥接和宿主验收。最终包应等待这些条件通过。

## 2. 重构前核实的事实（历史基线）

| 项目 | 现有实现及证据 | 意义 |
| --- | --- | --- |
| 动态控件禁用 | `ui/app.js` 的 `paused=cut||!!this.values.eq_mode`；`source/WebEqEditor.cpp::frame()` 在 `eq_mode=1` 时停止上报有效动态数据 | 当前灰色是主动限制，解除前端禁用不能补齐音频处理 |

## 3. 产品功能契约

| 能力 | 新 Linear Phase 目标 |
| --- | --- |
| 静态滤波 | Bell、Low Shelf、High Shelf、Low Cut、High Cut；保留现有频率、增益、Q、斜率范围 |
| 动态均衡 | Bell 和两类 Shelf 支持自动/手动阈值、现有 0–24 dB 向下动态范围及真实 GR |
| 切除滤波器动态 | 暂不增加；Cut 无静态增益旋钮，不能直接套用 Bell 的增益变化语义 |
| 声道位置 | 每段独立选择 Stereo、Left、Right、Mid、Side，允许混用 |
| 音色染色 | Linear Phase 保持干净；Tube/Discrete 的非线性音色继续属于另外两个模式 |
| 延迟 | 对给定采样率与质量设置固定；添加频段或开启动态不得改变延迟 |
| 动态控制显示 | 数字 GR 和响应图反映实际应用到音频的动态量，而不是尚未应用的检测目标 |
| 界面 | 保持现有设计；动态区使用已有旋钮及按钮，不另建第二套控制区 |
| 首期范围 | 完成向下动态和混合路由；正向扩展、外部侧链、频谱动态压制另外立项 |

首先交付一个完整可用的标准质量档。高质量档只在测得低频误差和实时开销后加入设置，不预先增加不可用选项。即使有多个档位，也不得在离线导出时自行改变质量或声音。

20 Hz–20 kHz 保留为参数范围；这不等于所有采样率及所有 Q 值都能达到相同精度。尤其 20–80 Hz、Q 接近 40 的极窄滤波，必须单独报告实际误差。低于 40 kHz 的采样率也不能产生真实的 20 kHz 音频，需使用明确的 Nyquist 边界策略。

## 4. 音频架构

### 4.1 先建立静态 2×2 传递矩阵

2×2 传递矩阵表示：两个输出都可以包含来自两个输入的滤波结果。不能继续只保存“左路多少 dB、右路多少 dB”。

令每段的线性幅度响应为 a(f)，I 为单位矩阵，通道投影矩阵为 P，该段响应为：

```text
B(f) = I + (a(f) - 1) P

P_Left   = [[1, 0], [0, 0]]
P_Right  = [[0, 0], [0, 1]]
P_Mid    = 0.5 * [[1, 1], [1, 1]]
P_Side   = 0.5 * [[1,-1],[-1, 1]]
P_Stereo = I

M(f) = B_24(f) ... B_2(f) B_1(f)
H(f) = exp(-j*w*D) * M(f)
```

以上是本次矩阵实现采用的数学定义。D 为共同延迟。按槽位顺序组合：混合 L/R 和 M/S 时矩阵通常不可交换，不能因 UI 按频率排列就改变处理次序。

四条路径为 L→L、R→L、L→R、R→R；交叉项允许为负，FIR 合成接口必须接受带符号的实数响应，不能把四个元素全部转换成无符号 dB 幅度。四路共用时间基准，使用原始输入历史，不能先覆写左输出再用于右路运算。

先用两个频段、一个单音和脉冲建立参考。静态全旁通应等于固定延迟直通；纯 L/R 的交叉项应为零；纯 M/S 应等价于编解码后的参考处理；混合两种基准应符合矩阵乘积。

### 4.2 动态控制与音频滤波拆分

从 `DynamicBand` 提取独立控制器，保留已有自动阈值、手动阈值、软拐点、最大衰减和立体声联动能力。控制器输出带时间戳的目标衰减；音频路径由最小相位实现或新 Linear Phase 实现消费。

新 Linear Phase 建议从输入增益后的 Pre-EQ 信号取检测支路，根据各段声道位置进行 L/R/M/S 投影，再做带内检测。检测支路可以使用 IIR，因为该支路不直接混入可听输出；必须校准其频段选择、包络时间和控制对齐。

兼容性注意：现有前三种模式的检测器位于频段级联中，会接收前序频段处理后的信号。不得在抽取控制器时顺便改变其检测源，否则旧工程声音会变。新 Linear Phase 首期采用上述固定输入检测，并明确与旧模式的触发差异；若以后统一检测源，需独立版本迁移。

静态与动态形状也应先保持当前语义：当前是静态滤波与附加动态衰减滤波级联，不应假定它严格等价于一个“静态增益减 GR”的 Bell。参考响应应使用二者幅度响应的乘积。更换为单段总增益模型属于另外的声音设计决策。

### 4.3 实时动态 Linear Phase

重构目标是带动态控制的矩阵 FIR 音频引擎，不是将当前 `DynamicBand::process()` 直接串在静态 FIR 后。前者需要真实的动态滤波响应；后者会引入额外最小相位滤波，却仍让界面显示 Linear Phase。

实施上先建立参考模型，再选择通过误差和性能门槛的优化路径：

1. 参数变化时，在非音频线程生成不可变的静态响应/动态响应缓存，通过预分配的单生产者单消费者队列交换；请求带版本号，只接受最新的完整结果。
2. 动态控制使用固定采样间隔或固定毫秒间隔；不得沿用“每 10 个宿主块重建”作为动态速度。第一轮原型可评估约 1–3 ms 的控制间隔，最终以突发测量和最坏 CPU 时间决定。
3. 根据实际动态量更新带符号矩阵响应，评估响应表插值、共享变换及分块卷积。不能未经测量就承诺在每次更新中对 24 段逐点重算、合成四个长核仍满足实时要求。
4. 核更新应使用相同输入历史，平滑过渡完整输出，并计入卷积帧边界。控制平滑或核间插值本身并不能证明没有爆音或调制伪影。
5. 参数连续扫动时保持已验证的完整核，后台赶不上时不阻塞、不应用半成品，也不静默切回最小相位。若实时预算不能满足，先优化再开放该能力。

第一阶段允许采用高成本参考实现验证数学正确性；最终实时实现必须另外通过小块长、多实例和高采样率压力测试。

### 4.4 检测、音频和显示对齐

为输入样本、控制包络和输出样本建立共同的采样时间轴，显式定义预读量、FIR 群延迟、处理帧缓冲延迟及核更新生效时刻。不能把“总延迟 5120”直接当作已经校准的动态预读。

数字 GR 应来自当前实际应用的控制量，并与输出时间对应；曲线区分用户目标与已生效响应。模式切换、BYP、按住试听、恢复播放和更换采样率，都需验证延迟保持和状态释放。

动态处理随时间变化，不能用静态滤波器的一条固定相位响应描述整个系统。验收表述应是“静态/冻结控制状态的核对称、共同延迟一致，动态过渡伪影经过测量与试听”，不得宣称动态全过程绝对零相位失真、无预振铃。

## 5. 参数和旧工程兼容

- 保留当前 323 个参数 ID、枚举、顺序和范围；`eq_mode` 仍为现有两值底层参数，UI 四模式映射不变。
- 新状态加入实现版本标记。旧 Linear Phase 工程可能保存 `bandN_dynamic=true`，但旧版实际上暂停动态；载入后不能自动变成压缩已生效。应保持旧声音，并通过明确升级操作启用新动态能力。
- 从新建实例或用户明确重新开启动态进入新版路径；兼容状态需要保存在工程中，并覆盖保存/恢复、撤销、预设和自动化测试。
- 旧混合 L/R/M/S 本身有错误。修复可能改变这些工程的声音，应在版本说明中列出，不能声称逐样本兼容。若需旧渲染兼容，把旧路径留在内部兼容层，不让新实例继续使用错误路由。
- 质量设置放到现有设置中，选项带实际延迟信息；用户此前移除的底部大块采样率/延迟栏不恢复。

## 6. 执行顺序与验证门槛

| 阶段 | 实施与可交付证据 | 通过后才做下一步 |
| --- | --- | --- |
| A：失败基线 | 接入混合路由测试；记录当前缺陷。补充 20–80 Hz 窄带、不同宿主块长、自动化阶跃基准 | 测试确实能捕获当前缺陷，不靠排除失败案例通过 |
| B：静态矩阵 | 完成四路有符号 FIR，共同延迟，保留固定槽位顺序 | 单音、脉冲、反相信号、两种路由顺序、随机组合与离线参考一致 |
| C：单段动态 | 一段 Bell 完成手动阈值、衰减、释放、音频时间对齐 | 实际音频有正确衰减；未触发信号保持静态参考；GR 与输出对应 |
| D：完整动态 | 自动阈值、Shelf、五种位置、24 段、混合静态/动态、版本兼容 | 44.1/48/96/192 kHz；64/128/257/512/1024 块长；实时时序与内存检查 |
| E：界面和发布 | 开放既有动态控件，修改桥接与能力提示；DAW 自动化/保存/重开/导出验证 | 原生、网页、格式、实际宿主和音乐试听分别有证据 |

建议量化门槛，属于拟定验收目标，尚非测得成绩：

- 静态单位矩阵输出相对延迟参考的最大误差不超过 1e-5；非零路由参考误差和预期零输出泄漏分别检查。
- 常规 Bell/Shelf（100 Hz–16 kHz、Q≤4、增益±12 dB）中心增益误差先以 0.2 dB 为目标；更低频、陡峭 Cut、极高 Q 逐项报告，不隐藏在宽松平均值中。
- 稳态动态衰减与目标误差先以 0.25 dB 为目标；改变宿主块长后触发/释放时刻偏移不超过一个内部控制周期加测量容差。
- 四通道矩阵的静态核共用群延迟；动态关闭、BYP 及质量不变时增删频段，宿主上报延迟不得跳变。
- 音频回调不分配、不等待锁、不等待后台结果。记录最坏耗时、峰值内存和多实例余量，不仅记录平均 CPU。
- 鼓组突发、齿音、持续低音、无信号、快速扫频、反相立体声、模式反复切换均需试听；明确记录预振铃和瞬态改变，不能只以单音通过代替听感。

## 7. 代码改动边界

预计集中在 `source/dsp/LinearPhaseEq.{h,cpp}`、`source/dsp/EqProcessor.{h,cpp}`、`source/dsp/DynamicBand.h`、状态升级逻辑及测试；界面只调整 `source/WebEqEditor.cpp` 与 `ui/app.js`、`ui/band-tools.js`、`ui/graph.js` 中能力判断和真实数据来源。

无需重做字体、图标、旋钮、炫彩频谱、稳定选峰或窗口布局。前三种模式的声音回归必须保持；不能借此顺便重新设计 Tube/Discrete。
